# Требования к ПО — Glucolog (нативное Android-приложение)

## 1. Цель и контекст

- Нативное Android-приложение на Kotlin + Jetpack Compose, Material 3 с фирменным цветом `#1D9E75`.
- `applicationId` = `com.koftamainee.glucolog`, minSdk 26, targetSdk 36.
- Приложение — наследник веб-версии Glucolog (та заморожена и остаётся на GitHub Pages без Google-интеграций).
- **Хранение данных — SQLite (Room)**, вместо localStorage веб-версии.
- **Основной источник глюкозы — приложение xDrip, установленное на том же устройстве.** Детали подключения (механизм, протокол, доступ к данным) — открытый вопрос, оставлен на изучение.
- Ручной ввод глюкозы **остаётся**, но является вспомогательным: используется для разовых замеров глюкометром, а не как основной источник.

## 2. Функциональные требования

### 2.1 Дневник по дням

Экраны и секции переносятся 1:1 из веб-версии:

- **Глюкоза**
  - Основной поток данных — показания xDrip (автоматически).
  - Приложение должно **работать в фоне**, чтобы постоянно получать данные из xDrip (без необходимости держать приложение открытым).
  - Ручной ввод — разовые замеры глюкометром; вспомогательный, не основной.
  - **График**: общая линия строится **только по данным xDrip**. Ручные замеры отображаются **отдельными точками без линии**.
  - **Цифры на графике**: на точках xDrip цифры **не отображаются** — при касании/проведении пальцем появляется вертикальная полоска (кроссхейр) с временем и значением. На точках ручных замеров цифры отображаются **постоянно**.
  - **Удаление глюкозы**: только для записей, введённых вручную (глюкометр). Данные, пришедшие из xDrip, удалению не подлежат.
- **Инсулин** — болюс и базальный (дозы + время).
- **Приёмы пищи** — 5 позиций (1-й/2-й завтрак, обед, полдник, ужин): время, голод (1–5), еда, физ. ощущения, эмоции.
- **Вода** — 0–8 стаканов.
- **Спорт** — да/нет + шаги.
- **Стул** — выбор опций (после еды / запор / диарея).
- **Сон** — «лёг»/«встал» + расчёт длительности.
- **Стресс** — нет / да / хронический.
- **Заметки** и **Выводы дня** — текст.
- **Журнал дня** — хронологический список записей с возможностью удаления (с подтверждением):
  - В журнал **не выводятся** показания глюкозы из xDrip.
  - Журнал содержит: ручные замеры глюкозы + болюс + базальный.
  - Удаление глюкозы из журнала — только для ручных замеров.

### 2.2 Навигация

- Переход между днями (стрелки), выбор даты через календарь.
- Быстрый возврат к сегодняшнему дню.

### 2.3 График и статистика дня

- **График дня**: линия глюкозы (только xDrip) + точки ручных замеров + болюс + базальный (сетка, диапазон 4–8 ммоль/л подсвечен).
- График строится по всем имеющимся данным. Если данных xDrip нет (приложение не установлено/не запущено) — линия отсутствует, остаются точки ручных замеров; приложение работает.
- **Статистика дня**: n, min/max, среднее, SD, число гипо (<4 ммоль/л) и гипер (>10 ммоль/л), тренд относительно вчера.

### 2.4 Импорт и экспорт данных

- Экспорт в **JSON** и **CSV**, импорт из **JSON** и **CSV**.
- Форматы полностью совместимы с веб-версией (тот же JSON-структур, те же колонки CSV) — чтобы можно было переносить данные между вебом и приложением.
- **Импорт при первом запуске** — перенос накопленных данных из веб-версии (файлы, экспортированные из веба).
- Валидация файлов, понятные сообщения об ошибке.
- При импорте в непустую базу — **выбор из двух стратегий пользователем**:
  - (а) **заменить** все данные;
  - (б) **объединить** по дням (обновить существующие дни, добавить новые).

### 2.5 Тема

- Material 3, светлая / тёмная / системная.

### 2.6 Онбординг

- Короткий туториал при первом запуске (аналог веб-версии): навигация по датам, ввод данных, импорт.

## 3. Модель данных (Room)

Таблицы (нормализованные, с версией схемы и миграциями):

| Таблица | Поля | Источник в вебе |
|---|---|---|
| `day` | `date` (PK, YYYY-MM-DD), `water`, `sport`, `steps`, `sleep_start`, `sleep_end`, `stress`, `notes`, `conclusions` | ключ дня + скалярные поля |
| `glucose` | `id`, `date`, `h` (час float), `g` (ммоль/л), `source` (`xdrip`/`manual`) | `db[date].glucose[]` |
| `insulin` | `id`, `date`, `h`, `bolus`, `basal` | `db[date].insulin[]` |
| `meal` | `id`, `date`, `key` (`breakfast1`…`dinner`), `time`, `hunger`, `food`, `phys`, `emo` | `db[date][mealKey]` |
| `stool` | `date`, `option` (составной PK) | `db[date].stool[]` |

- Поле `source` в `glucose` — новое по сравнению с вебом: нужно для разделения линии xDrip / точек ручных замеров, ограничения удаления и фильтрации журнала.
- Импорт JSON/CSV отображается на эти таблицы; экспорт воспроизводит формат веб-версии.

## 4. Открытые вопросы

1. **xDrip**: механизм получения данных (локальный API приложения xDrip, общий доступ/шаринг данных, чтение БД xDrip и т.п.), частота обновления, обработка перезапусков. **Оставлено на изучение**, решается отдельно.
2. **Ручной ввод vs xDrip**: приоритет при отображении, что делать с дублями (если xDrip и ручной замер совпадают по времени).

## 5. Нефункциональные требования

- Работа без сети (приложение полностью локальное; интернет не требуется).
- Поддержка тёмной/светлой темы.
- Данные хранятся только на устройстве; резервное копирование — через экспорт JSON/CSV (пользователь сам копирует файлы).
- minSdk 26 (Android 8.0+).
- CI: сборка debug APK на каждый push/PR; релиз с подписанным APK по кнопке (уже настроено).

## 6. Этапы реализации (ориентир)

- **Этап A** — скелет: Room-схема + миграции, экран дня со всеми секциями 1:1, навигация по датам.
- **Этап B** — график дня и статистика дня (перенос логики веб-версии).
- **Этап C** — импорт/экспорт JSON и CSV, импорт при первом запуске.
- **Этап D** — интеграция xDrip (после выяснения деталей), различение `xdrip`/`manual`.
- **Этап E** — онбординг, темы, полировка UI, релиз.
